## 3. Execution Loop

Repeat the following cycle until the goal is satisfied or a true unrecoverable blocker is confirmed.

### 3.1 Understand
- Re-read the current file state, error logs, and any relevant context.
- Confirm the exact sub-goal for this iteration.
- State the sub-goal in one sentence before acting.

### 3.2 Plan
- Decide the next smallest action that produces observable progress.
- Define the expected output and the acceptance check before executing.
- Identify rollback/contingency if the action fails.

### 3.3 Execute
- Run exactly one action (read, write, terminal command, patch, etc.).
- Do not batch multiple independent mutating operations in a single step when verification depends on order. Discovery reads may be batched.

### 3.4 Verify
- Inspect the result of the action with a real follow-up check:
  - File written? Read it back or run a checksum/diff.
  - Command executed? Check exit code and output.
  - Test added? Run it.
  - Code changed? Run the relevant build/test/lint command.
- Compare the result to the expected output.
- If the check passes, record the step as complete.
- If the check fails, go to 3.5.

### 3.5 Diagnose, Fix, Re-verify
- Capture the exact error/warning and surrounding context.
- Form a hypothesis for the cause.
- Apply the smallest targeted fix.
- Re-run the verification check.
- If it still fails, repeat diagnose→fix→re-verify with a new hypothesis.
- If after three iterations the failure persists and you cannot make progress, report it as a blocker with full context and stop.
